# 照片分享前隐私体检与脱敏工具 · 规格卡 v1.4

> 项目代号：PhotoCheck ｜ 周期：2026-11 ~ 2027-04（24 周）｜ 团队：3 人（A / B / C）
> v1.4 修订：2026-11-01 ｜ 数据契约升级为 v4 ｜ v1.3 / v1.2 / v1.0 保留作历史

## 定位（v1.4 修订）

**面向中文校园场景的手机拍摄单据、证件与截图，构建虚构或授权样本的测试集与可复现评测协议，量化本地检测与脱敏方法的漏检、误报、处理后残留与过度脱敏；并以本地原型演示"检测 → 用户确认 → 脱敏 → 导出复检"闭环。**

**系统总定义**

| 项 | 内容 |
|---|---|
| 系统输入 | 一张本地 JPG / PNG 图片（HEIC 可选） |
| **用户输出** | 一张**不覆盖原图**的脱敏副本 + 页面内简短结论（发现项计数、处置情况、复检结果、边界说明） |
| 研究输出 | 测试集、标注规范、评测协议、有效性报告——用于结题评审，**不是**每次处理图片时给用户的长报告 |
| **隐私定义** | 只处理**位置或字段明确、能自动检测、处理完能再验证**的个人信息线索 |

> 对用户输出处理后的照片；对评审输出数据集与实验报告。这两件事不能混。

三句话解释：

1. **产品是载体，评测是资产。** 结题时能独立成立的是「数据集 + 评测协议 + 有效性报告」，不是「功能很多的打码工具」。
2. **输入域收窄到"含有明确文字风险对象"的图像**：快递单、证件、门牌、含敏感信息的聊天截图（首版只从中识别**手机号与身份证号**，其余类型见第 5 条边界）。风景照、纯人像作为**扩展输入**，结果单独汇报，**不进入核心结论**。
3. **不做算法创新**。OCR、人脸、二维码都是成熟模型；本项目的贡献是**场景化评测 + 闭环工程**。

### 0.2 共享契约 v4（三人共同遵守，改动需三人同意）

机器可校验版本位于 `../photocheck/contract/schema/photocheck-v4.schema.json`，示例与适配器位于 `../photocheck/contract/`。所有可序列化记录必须带 `contract_version: "photocheck/v4"`，禁止未知字段。

**五类独立记录**

| 记录 | 职责 | 关键规则 |
|---|---|---|
| `ImageDescriptor` | 描述规范化工作图 | `width` / `height` 为方向矫正后的像素尺寸；坐标系固定为 `top_left_pixels` |
| `Detection` | 只读检测事实 | 只由检测器产生，不含用户选择、复检状态或原始敏感值 |
| `Decision` | 用户当前决定 | 只有 `redact` / `retain`；每项 Finding 最多一个当前决定 |
| `RedactionPlan` | 像素处理计划 | 由 `redact` 决定和手动框生成；默认 `solid` 遮盖 |
| `VerificationReport` | 最终文件复检结论 | 必须绑定 `plan_revision`；过期结果禁止用于当前计划 |

**ImageDescriptor**

~~~json
{
  "contract_version": "photocheck/v4",
  "record_type": "ImageDescriptor",
  "image_id": "image-demo-001",
  "width": 1600,
  "height": 1200,
  "orientation": "exif_transposed",
  "coordinate_space": "top_left_pixels"
}
~~~

**Detection**

~~~json
{
  "contract_version": "photocheck/v4",
  "record_type": "Detection",
  "id": "det-phone-001",
  "image_id": "image-demo-001",
  "kind": "text",
  "subtype": "phone",
  "bbox": [520, 410, 220, 42],
  "detector_score": 0.96,
  "evidence": "ocr_rule",
  "risk": 2,
  "details": {
    "masked_preview": "138****0000"
  }
}
~~~

| 字段 | 规则 |
|---|---|
| `id` | 在一个 `image_id` 内唯一；多个检测器不得复用同一个 ID |
| `bbox` | 方向矫正后工作图的 `[x, y, width, height]` 整数坐标；`kind=meta` 时必须为 null |
| `detector_score` | 0～1 或 null；只用于排序与阈值过滤，不是校准概率 |
| `evidence` | 与 `kind` 固定对应：meta=exif，text=ocr_rule，qr=qr_payload，face=face_box |
| `risk` | 固定 1 / 2 / 3 级策略标签，与 `detector_score` 分离 |
| `details` | 按 kind 使用严格字段集合；不得塞入原始文字、payload 或 EXIF 值 |

`kind` 与 `subtype` 枚举：

| kind | 允许值 | `details` 必填项 |
|---|---|---|
| meta | gps, datetime, device, serial, thumbnail, software | 无；允许安全 `masked_preview` |
| text | phone, idcard | `idcard` 必须有 `idcard_check=pass/fail/na` |
| qr | qr_wechat_card, qr_wechat_group, qr_wechat_pay, qr_alipay, qr_wifi, qr_vcard, qr_contact, qr_geo, qr_code, qr_link, qr_unknown | `decodable` 必填；只允许域名 / SSID 等安全摘要 |
| face | face_region | 无 |

**Decision**

~~~json
{
  "contract_version": "photocheck/v4",
  "record_type": "Decision",
  "finding_id": "det-phone-001",
  "action": "redact",
  "revision": 1
}
~~~

- v4 删除 `selected`、`skip`、`default_action` 和 `verify_status`。
- 用户取消处理写 `retain`；用户确认遮盖写 `redact`。
- 任何决定变化都递增 `revision`，旧验证报告立即失效并显示 `pending`。
- **元数据不接受 Decision**。系统始终清除整张图的源元数据，Finding 只用于告知发现了哪类元数据。

**RedactionPlan**

~~~json
{
  "contract_version": "photocheck/v4",
  "record_type": "RedactionPlan",
  "image_id": "image-demo-001",
  "revision": 1,
  "items": [
    {
      "id": "redact:det-phone-001",
      "finding_id": "det-phone-001",
      "bbox": [520, 410, 220, 42],
      "method": "solid"
    },
    {
      "id": "manual-face-001",
      "finding_id": null,
      "bbox": [150, 180, 300, 330],
      "method": "solid"
    }
  ]
}
~~~

- 每个 `redact` Decision 必须对应且只对应一个计划区域。
- 手动补框作为 `finding_id=null` 的独立计划区域，不伪造为 Detection。
- 首版默认 `solid`；`blur` / `mosaic` 只能作为显式附加选择。

**VerificationReport**

~~~json
{
  "contract_version": "photocheck/v4",
  "record_type": "VerificationReport",
  "image_id": "image-demo-001",
  "plan_revision": 1,
  "disposal_state": "passed",
  "checks": [
    {
      "region_id": "redact:det-phone-001",
      "status": "passed",
      "method": "ocr"
    }
  ],
  "residuals": [
    {
      "region_id": null,
      "finding_id": "det-qr-001",
      "reason": "retained",
      "kind": "qr",
      "subtype": "qr_contact",
      "masked_summary": "qr/qr_contact"
    }
  ]
}
~~~

| 字段 | 规则 |
|---|---|
| `disposal_state` | `not_applicable`：无待处理区域；`pending`：未复检或存在 not_run / not_applicable；`failed`：至少一个区域失败；`passed`：全部待处理区域通过 |
| `checks` | 每个计划区域最多一个当前结果；status=passed / failed / not_run / not_applicable |
| `residuals` | 只允许 `retained` 或 `verification_failed`，只存 kind/subtype 级掩码摘要 |

**泄漏与迁移红线**

- 原始文字、二维码 payload、EXIF 值和内嵌缩略图不进入任何可序列化 v4 记录；需要时仅通过进程内短期 SecretStore 引用。
- 日志、异常、Gradio state、历史记录和 CSV 不得自动序列化 Detection 对象。
- v3 历史数据只允许无冲突迁移：`selected=true + action=hide → redact`，`selected=false + action=keep|skip → retain`；其余组合拒绝。
- 含 `text_ref`、`payload_ref`、`raw_exif` 明文的历史记录直接拒绝，旧 `verify_status` 不受信任，必须对 v4 计划重新复检。

**界面文案强制规定**

- 只能显示「**本次计划中待处理区域未发现残留**」
- 禁用「已经处理干净」「可以安全分享」「无隐私风险」

1. **原始 text / payload 永不落盘**。日志、历史、报告只存掩码。
2. **报告与面板默认只放脱敏后的图**，不放原图缩略图（原图缩略图 = 把隐私写进报告）。
3. **不做安全承诺**。禁用"已确保安全""可以放心分享""发给熟人问题不大"。只陈述事实：「未检出……（基于 X 检测器）」。
4. **不给社交建议**。工具不判断"该不该发""发给谁"，只列风险项，由用户决定。
5. **演示一律用虚构样本**（自打印假证、自写假单号、自己生成的二维码），不使用他人真实信息。
6. **不做人脸识别**，不引入 embedding 模型。

### K-04 敏感实体识别（基础 2 类）

| 项 | 内容 |
|---|---|
| 负责人 | **A** |
| 人日 | 2.5 |
| 周次 | W4 末–W5 |
| 依赖 | K-03 |

**输入**：文字块列表
**输出**：Finding 列表（kind=text）

**工具**

| 环节 | 工具 | 用法 |
|---|---|---|
| 正则 | Python re | 预编译 pattern |
| 身份证校验 | 自写约 15 行 | ISO 7064:1983 MOD 11-2，输出三态 |
| 上下文 | 自写 | 关键词在 box 附近 ±1 行 |
| 归一化 | 自写 | 全角转半角、去空格与连字符 |

**基础 2 类**

| # | 类型 | 规则 | 风险 |
|---|---|---|---|
| 1 | 手机号 | 1[3-9] + 9 位，两侧非数字，允许空格横线 | 2 |
| 2 | 身份证号 | 18 位（末位可 X）+ 校验位，**输出 idcard_check 三态** | pass=3 / fail=2 |

> **v1.3.1 收窄**：快递单号、门牌/楼栋移到后置，对应立项申请书三类中的"敏感明文"（另两类是敏感二维码、EXIF）。只有两个类"每类 ≥3 正样本"这条验收也就更容易做扎实。省下的时间不砍人日，改用在对两个类的阈值调优和负样本测试上。

> **v1.3 修正**：v1.2 要求"篡改一位校验位必须不报"，这在真实场景会**漏掉打错一位的证件号**，而打错的号码同样泄露信息。改为三态：校验不通过仍提示，但降为 risk 2 并标注「格式像身份证，校验位未通过（可能录错）」。

**验收标准**

- [ ] 每类 ≥3 正样本、≥3 负样本
- [ ] 正样本召回 ≥ 80%；负样本误报 ≤ 2 处/张
- [ ] 校验位正确的样本 → idcard_check = pass（risk 3）
- [ ] 篡改一位的样本 → **不得标 pass**，但必须保留为 idcard_check = fail（risk 2）
- [ ] 手机号被拆成 138 0013 8000 时仍能识别

**降级**：若身份证误报偏多 → 收紧上下文关键词（"身份证""公民身份号码"邻近才报），三态照旧保留。

### K-09 复检器（核心卡）

| 项 | 内容 |
|---|---|
| 负责人 | **B** |
| 人日 | 2.5 |
| 周次 | **W2 起分四次增量，W8 汇总** |
| 依赖 | 按增量逐步接入 |

**增量排期**

| 阶段 | 周次 | 接入什么 | 产出 |
|---|---|---|---|
| 9a | W2 | EXIF 检查（exiftool） | 能判元数据是否清干净 |
| 9b | W4 | OCR 复检 | 能判文字是否还读得出 |
| 9c | W5 | 二维码复检 | 能判码是否还可解 |
| 9d | W6–W8 | 人脸复检 + 汇总成 VerificationReport | 四检（人脸项先用 mock 桩，K-07 交付后接真；若 K-07 降级为手动补框，人脸项记 not_applicable，按三检验收） |

**核心逻辑（两条独立结论）**

~~~text
对 RedactionPlan 的每个 item：
    用独立代码路径重新检测该区域/该类型
    passed  -> 计入通过
    failed  -> disposal_state = failed，写入 residuals(reason=verification_failed)
    not_run / not_applicable -> disposal_state = pending

对 action=retain 的 Decision：
    -> 写入 residuals(reason=retained)，不参与 disposal_state

若 RedactionPlan.items 为空：
    -> disposal_state = not_applicable

VerificationReport.plan_revision 必须等于当前 RedactionPlan.revision；
任何 Decision 改变都递增 revision 并使旧报告失效。
~~~

**本卡能力边界（v1.3 明确写死）**

复检用的是与检测阶段**同一套模型**，所以它只能证明"同一检测器不再读出"，**不能**证明：

- 人类无法识别（可能仍然可读）
- 没有首次漏检（residuals 只包含已检出对象中的 retained / verification_failed）

这两件事分别由 **R-03（导出图重检）** 与 **R-04（第二 OCR + 人工抽检）** 回答。报告里必须这样写，不能越界表述。

**工具**

| 检查 | 工具 | 方法 |
|---|---|---|
| EXIF | ExifTool + piexif | 独立进程重新读文件 |
| 二维码 | pyzbar 重跑 | 对已遮区域解码 |
| 文字 | RapidOCR 重跑 | 对已遮区域 OCR |
| 人脸 | mediapipe 重跑 | 仅对 RedactionPlan 中的人脸区域 |
| 结构 | Pillow | 尺寸、可打开、非全黑 |

**验收标准**

- [ ] 含「redact 决策但未处理」的图 → disposal_state = failed
- [ ] 干净负样本 → 不报错、不误判失败，disposal_state = not_applicable
- [ ] 用户全部保留 → disposal_state = not_applicable，residuals 有 retained 项
- [ ] 只遮二维码一半的图 → 必须 fail
- [ ] 正确处理 → disposal_state = passed
- [ ] 四项 check 能单独显示（人脸项 not_applicable 时保持 pending，不伪装通过）
- [ ] **界面文案为「本次计划中待处理区域未发现残留」**，无"已确保安全"类表述
- [ ] 复检耗时 ≤ 处理耗时的 2 倍

**降级**：OCR 复检太慢 → 只对 RedactionPlan 区域做局部复检。
