# 与 C 开始最小界面和数据集的对接清单

日期：2026-11-06

## 1. C 当前可以直接使用的接口

环境自检：

```powershell
python photocheck\scripts\check_environment.py
```

核心调用：

```python
from photocheck.contract import build_redaction_plan
from photocheck.core import ingest_image, process_and_export
from photocheck.detectors import analyze_a

with ingest_image(path) as ingested:
    envelope = analyze_a(
        ingested.image,
        ingested.descriptor["image_id"],
    )
    detections = [
        *ingested.detections,
        *envelope.detections,
    ]
    decisions = make_user_decisions(detections)
    plan = build_redaction_plan(
        ingested.descriptor,
        detections,
        decisions,
        revision=1,
    )
    result = process_and_export(
        ingested,
        plan,
        output_dir=output_dir,
        detections=detections,
        decisions=decisions,
        run_full_recheck=True,
    )
```

## 2. 最小界面必须展示

### 检测阶段

- 原工作图；
- Detection 边框；
- subtype、risk、evidence；
- 掩码后的安全摘要；
- 元数据风险提示，但元数据项不得提供“保留”决策。

### 用户确认

每个非元数据 Detection 生成一个 Decision：

```text
redact
retain
```

用户修改任一决定后：

- `revision += 1`；
- 重新生成 RedactionPlan；
- 旧 VerificationReport 立即失效。

### 手动补框

- bbox 使用 `top_left_pixels` 坐标；
- 默认 `solid`；
- 二维码区域强制 `solid`；
- 手动框作为 `finding_id=null` 的 RedactionPlan item。

### 结果页面

显示：

- 脱敏后图片；
- `disposal_state`；
- 计划区域检查结果；
- 已知保留项；
- 整图重检的 `unplanned_count`；
- 边界声明。

通过文案只能使用：

```text
本次计划中待处理区域未发现残留
```

禁止：

```text
已经处理干净
可以安全分享
无隐私风险
```

### 下载

- 只下载 K-02 生成的新文件；
- 不覆盖原图；
- 文件名不包含原文件名；
- 元数据残留或导出结构错误时不提供下载；
- 内容复检失败时提供重新遮盖，不提供“忽略并下载”的默认按钮。

## 3. 状态映射

| disposal_state | UI |
|---|---|
| `not_applicable` | 没有需要处理的计划区域 |
| `pending` | 复检未完成或检测器不可用 |
| `failed` | 至少一个计划区域仍有残留 |
| `passed` | 所有计划区域在本次复检中通过 |

`passed` 不等同于整张图绝对安全。

## 4. 数据集对接

C 需要建立：

```text
dataset/
  dev/       >= 40 images
  lock/      >= 20 images
  annotations.csv
  label-guide.md
  manifest.json
```

标注 CSV 至少包含：

```text
file
set
scene_id
group_id
kind
subtype
bbox
should_hide
difficulty
note
```

规则：

- 同模板、同场景、同一人多角度整组进入同一集合；
- lock 集冻结并记录哈希；
- 困难样本不少于 30%；
- 负样本包含“像手机号但不是”和“像身份证但不是”的样本；
- 样本必须虚构或取得授权；
- 用户失败样本不得自动回流；
- n < 30 的指标只能标为开发参考。

## 5. 评测对接

第一层：检测质量

- 对象级召回；
- 精确率；
- 每图误报数；
- 按 subtype 和 n 分组。

第二层：最终导出文件

- OCR 残留；
- 二维码 detected / decodable；
- 人脸残留或 unavailable；
- 元数据残留；
- 残留原因：漏检 / 用户保留 / 遮挡失败。

第三层：过度脱敏

- 非目标区域被误遮数量；
- 是否影响非敏感内容阅读。

## 6. C 不应做的事

- 不直接修改 Detection 原始字段；
- 不把原始文字、payload 写入 UI state、CSV、日志或 Gradio 历史；
- 不根据 detector_score 宣称概率；
- 不用 lock 集调参；
- 不用 4–5 个合成对象宣称通用召回率；
- 不把整图重检的误报直接归因于遮盖失败。
