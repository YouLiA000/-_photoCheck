## 2. Requirements 中文注释结论

负责人：A

建议保持所有依赖名称和版本号不变，只把 requirements 中的中文注释改成英文或删除注释。

结论：可以解决当前 Windows pip 的 GBK 解码错误。

依据：

- 原文件失败原因是无 `encoding` 的 UTF-8 中文注释被 pip 按 GBK 读取；
- 使用完全相同版本、仅将注释改为 ASCII 的临时文件后，`pip install --dry-run` 在未设置 `PYTHONUTF8=1` 时可以正常解析；
- 因此问题在文件编码兼容性，而不是依赖版本本身。

推荐文件内容：

```text

# Runtime: Python 3.11

numpy==1.26.4

rapidocr-onnxruntime==1.4.4

```

不要使用 BOM，不要在注释中保留中文。

B 不直接修改 A 的原始 requirements；A 完成 ASCII 化后，B 在集成时校验内容并更新项目依赖。

## 6. P0：修正二维码复检语义

A 当前 `probe_region()` 只统计可解码二维码：

```python
residual_qr_decodable = sum(
    1 for hit in detect_qr(...)
    if hit.decodable
)
```

这会漏掉“检测到二维码但无法解码”的区域。

K-09c 必须区分：

```text
residual_qr_detected
residual_qr_decodable
```

判定规则：

- `detected = 0`：没有发现码，不能证明绝对没有码；
- `detected > 0, decodable = 0`：存在未解码残差，至少 `pending`；
- `decodable > 0`：内容仍可读取，必须 `failed`；
- 检测器 unavailable：保持 `pending`，不能判 passed；
- 实心遮盖后仍能检测/解码：`failed`。

最终文案继续限制为：

```text
本次计划中待处理区域未发现可解码残留
```

不能写成“安全”或“不可识别”。

## 7. P1：重写 BC-0007 静区测试

当前 A 测试：

```text
test_quiet_zone_is_what_makes_reeval_decode
```

在本机失败：

- 紧贴 bbox 无外扩时，pyzbar 仍能解出；
- 默认外扩时也能解出；
- `probe_region()` 返回 `residual_qr_decodable=1`。

说明生产代码的默认外扩有效，但测试对“无外扩必须失败”的假设不稳定。

新测试应验证行为而不是依赖特定解码器：

1. 可见、未遮盖的 Detection bbox 经 `probe_region()` 必须发现二维码；
2. 完全实心遮盖后不得解出；
3. 静区外扩不得越出图片边界；
4. 外扩不得把明显位于目标区域外的二维码拉进来；
5. 用 mock/受控 ROI 验证外扩参数确实生效；
6. 对 pyzbar 和 cv2 两个后端分别记录行为，不做“无外扩必然失败”的跨后端断言。

验收：

```text
全套 A 测试可一次执行并正常退出；
使用 -x 时不出现已知失败；
最终打印真实 passed/failed 数量，而不是仅输出到 100% 后挂起。
```
