## 指标定义（与 C 的评测协议必须一致）

| 指标 | 定义 |
|---|---|
| 匹配 | 同一 subtype 且 bbox 的 IoU ≥ 0.5，视为命中；`kind=meta` 无 bbox，按 subtype 出现与否匹配 |
| 召回 | 命中数 / 标注真值数 |
| 漏检 | 有真值但无任何检出 |
| 误报 | 无真值却报出的条数，单位 **处/张**（验收线 ≤2） |
| 精确率 | 命中数 / 全部检出数 |

## 怎么对比两次提交

```bash
# 提交前：存一份快照
C:/venvs/photocheck/Scripts/python.exe scripts/bench_ocr.py samples/dev --repeat 3 \
    --out reports/t_ocr_<tag>.json
C:/venvs/photocheck/Scripts/python.exe scripts/badcase_index.py

# 提交后：同参数再跑一次，比较两个 JSON 的 summary 段
```

对比时必须同时看三件事，只看其中一项会得出错误结论：

1. **T_ocr 是否超过 2059 ms** —— 超了就是 K-03 验收失败，不是"稍慢一点"。
2. **召回是否下降** —— 召回掉了 5% 而速度提升 2 倍，是把检出换成了速度，不能算改进。
3. **badcase 是否新增** —— 新增条数比任何指标都灵敏，指标只会在样本上体现，badcase 会立刻暴露。
